# CryoHydro

This package contains the CryoHydro model and a limited training-and-output example. It includes glacier storage and melt, snow, soil moisture, groundwater, Stefan freeze/thaw, and river-network routing. Dynamic parameters are generated by an LSTM; static and routing parameters are generated by separate KAN-style networks with radial basis functions. There are no baseline/residual model variants, model registries, old-name adapters, or grid-search entry points in this release.

## Run

Use Python 3.12 and install the dependencies in `requirements.txt`. PyTorch must be installed with the CPU/CUDA build appropriate for your machine. The checked environment is Python 3.12.10, NumPy 2.4.0, and PyTorch 2.7.1; GPU checks use CUDA 11.8. CPU is supported, but the full 826-basin example is substantially slower on CPU.

From this directory:

```powershell
python -B train/train_cryohydro.py
python -B train/run_cryohydro.py
```

The device is selected automatically. Use `--device cpu` or `--device cuda:0` to choose explicitly. Both scripts work from any working directory because the default data directory is resolved relative to this package. `--data-dir PATH` selects another directory containing the same input files; checkpoints and outputs are then written underneath that directory.

The default release demonstration performs **one epoch with one training window**. To perform more optimization:

```powershell
python -B train/train_cryohydro.py --epochs 100 --steps-per-epoch 16
python -B train/run_cryohydro.py --chunk-days 90
```

Network widths, parameter groups, learning rates, sequence length, warm-up and memory chunk sizes are defined directly in `config/cryohydro_config.py`. The physical model is instantiated directly; no model-name dispatch is required.

To check the released data contract and saved example:

```powershell
python -B -m unittest discover -s tests -v
```

## Minimum example period and privacy

The existing training implementation uses a **730-day sequence with the first 365 days reserved for spin-up**. The manuscript describes the LSTM/KAN architecture, Muskingum routing and station-normalized squared-error loss (NSE*), but does not explicitly specify the 730/365 lengths. These temporal settings are retained from the implementation rather than invented as manuscript requirements.

The release contains exactly one such sequence:

| File | Coverage | Purpose |
|---|---|---|
| `data/dynamic_data.npz` | 1959-01-01 to 1960-12-30, 730 days | First 365 days spin up the model; next 365 days are used for fitting |
| `data/target_data.npz` | 1960-01-01 to 1960-12-30, 365 days | Only the first 365 dates from the supplied original target file |

The preceding 1959 ERA5 forcing was extracted to provide genuine meteorological spin-up; it is not a repetition or synthetic padding of 1960. No observations are released for the spin-up year. The full original target file, later target observations, full-period target statistics, extra AET/SWE targets and private backup files are not included. Missing observations remain NaN. Four of the nine listed stations have streamflow observations during this limited period; the others are retained as station metadata with missing targets.

All released target observations are used for the training example. There is **no independent validation/test set in this minimum package**. Metrics exported by this example are training-period diagnostics and must not be reported as paper validation/test skill. The example cannot reproduce the paper's 1960–1999 calibration, 2000–2005 validation and 2006–2015 test results; those require the corresponding full research data and calibration runs.

## Inputs

All inputs and generated files are under `data/`.

- `dynamic_data.npz`: `data` has shape `(11, basin, time)`, with `variables`, `dates`, `basin_ids`, and a JSON `config`. Variable order is `prcp, tmean, tmax, tmin, srad, lrad, pres, shum, wind, pet, doy`. LAI is not a forcing input. Temperatures are in °C; pressure is Pa; precipitation and PET are mm/day; shortwave/longwave radiation are W/m²; specific humidity is kg/kg; 10 m wind speed is m/s.
- `static_data.npz`: `data` is `(attribute, basin)`, with `variables`, `basin_ids`, and JSON metadata. Areas are m², soil/active-layer depths mm, glacier storage m³ water equivalent, glacier elevation m, and fractions dimensionless. Basin order must match the forcing.
- `target_data.npz`: `data` is `(2, station, target_time)`, with variables `runoff` (mm/day) and `streamflow` (m³/s), dates, station outlet basin IDs, station codes and JSON metadata. Training uses streamflow. Target dates are matched explicitly to forcing dates; target observations are not required for the initial spin-up.
- `basinatlas_topology.csv`: `HYBAS_ID, NEXT_DOWN, UP_AREA`; upstream area is km² in this CSV and is converted to m² for channel flow conversion. `NEXT_DOWN=0` denotes an outlet. Every modeled basin must have one row; cycles are rejected.
- `basinatlas_station.csv`: station-code/outlet correspondence for reference. The target NPZ contains the station order used by the model.

The model loader accepts this one explicit schema. It does not infer legacy layouts or silently convert units. The provided old forcing has already been reordered, LAI removed, pressure converted from hPa to Pa, and the period limited during release preparation. Dynamic and static normalization is fitted from the training example and saved in its checkpoint. Output generation always uses the checkpoint's statistics.

## Model and training settings

This release follows the manuscript's **Muskingum** routing and **NSE*** loss: each station's valid squared errors are normalized by its training standard deviation plus 0.1; stations with observations are averaged equally. There is no added log-flow or auxiliary SWE objective. The supplied source previously defaulted to daily retention routing and a mixed low-flow objective; this release explicitly selects the routing/objective described in the manuscript. It should not be treated as the exact configuration of previously generated retention-routing checkpoints.

The network settings retained from the supplied implementation are LSTM hidden size 256, one recurrent layer, eight physical members, static KAN hidden size 128 and routing KAN hidden size 32. The default optimizer is AdamW with learning rate 0.0002, a routing learning-rate multiplier of 0.3, and gradient clipping at 0.5. Fixed parameter bounds and all physical equations remain in `phy_models/cryohydro.py`.

Training windows have independent initial states. Within each window, the LSTM state is carried across parameter chunks. Physical spin-up is not scored and does not accumulate physical-state gradients. Activation checkpointing reduces peak memory without detaching the subsequent scored physical trajectory. Output generation advances continuously from the first forcing date, carrying both LSTM state and all physical/routing states across output chunks.

## Outputs

- `data/checkpoints/CryoHydro.pt`: model weights, explicit configuration, input version, parameter groups, normalization and training history. Only weights/configuration are loaded by `run_cryohydro`; no model registry or legacy migration is used.
- `data/training_history.csv`: optimization loss by epoch.
- `data/outputs/CryoHydro_outputs.npz`: outputs `(variable, basin, time)`, dates, IDs, station predictions/targets, metrics, static/routing parameters and ensemble-mean dynamic parameter trajectories. All 730 output days are retained; the first 365 are spin-up. The target array is NaN during spin-up and at other missing observations.
- `data/outputs/station_metrics.csv`: NSE, KGE, correlation, variability/mean ratios, RMSE and biases computed on released training observations after spin-up. Stations without sufficient observations receive NaN metrics.
- `data/outputs/metadata.json`: units, period, configuration and interpretation of saved arrays.

Streamflow is m³/s. Q0/Q1/Q2 are local reservoir runoff components in mm/day, not routed station discharges. Freeze/thaw depth, SWE and soil/groundwater stores are mm; glacier storage is m³ water equivalent; glacier fraction is dimensionless. Saved `parK` is the normalized learned Muskingum K control; it must not be interpreted directly as lag hours.
